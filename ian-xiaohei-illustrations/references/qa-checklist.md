# QA Checklist

## 必过项

- 比例正确（默认 16:9 横版）。
- 背景是干净白底。
- 有当前 IP 角色（默认小黑）。
- 当前 IP 角色承担核心动作，不只是装饰。
- 没有复刻旧案例构图，而是为当前文章生成了新隐喻。
- 画面怪诞、有创意、有意思。
- 简洁清爽，主体不超过画面约 60%。
- 一张图只讲一个核心结构。
- 中文标注少、短、能读。
- 橙色只用于主路径或箭头。
- 红色只用于重点、问题、提醒或结果。
- 蓝色只用于补充说明、反馈或系统状态。

## 机器可检查的 QA (客观)

以上检查是主观的。其中两项可以被机器验证——用仓库里的辅助脚本作为每个保存的 PNG 的硬性门槛：

```bash
python tools/check_image.py assets/<slug>-illustrations/01-topic.png --aspect 16:9
```

它会断言 (1) 图片确实是目标比例，以及 (2) 至少约 35% 的像素是接近白色的（“大量留白”规则）。如果你不在仓库内，也可以内联做同样的检查：读取 PNG 尺寸以确认比例，并估算近白色像素的比例。（辅助脚本的留白检查需要 Pillow；没有它，只会强制检查长宽比。）

对于**标注**，客观检查是**回读**：看着生成的图片，读出每个手写标注，并与你期望的文字比较。不匹配（错字/乱码/词不达意）就算失败——用更少/更短的标注重新生成，或退回到无文字图片+图下说明的模式 (SKILL.md 第4步)。这需要视觉回读，因为只有你知道预期的文字是什么。

## 失败信号

出现以下情况，重生成或局部编辑：

- 左上角有“常见坑 / Workflow / 系统架构图 / 路线图”等标题。
- 当前 IP 角色像吉祥物、表情包或可爱卡通。
- 画面像 PPT、课程课件、正式流程图。
- 元素太多、箭头太多、节点太多。
- 文字变成大段解释。
- 背景有纸纹、阴影、渐变、米色、噪点。
- 真实 UI 截图或科技感界面。
- 中文错字严重或标注不可读。
- 画面太死板，没有荒诞隐喻。
- 和 `assets/examples/` 里的旧案例构图过于相似。

## 迭代方法

- 太普通：让当前 IP 角色成为动作主体，加入一个奇怪但成立的隐喻。
- 太复杂：删节点，只保留一个动作和 3-5 个短标注。
- 太可爱：强调 deadpan、blank serious expression、not cute、not mascot。
- 太 PPT：去掉标题、边框、整齐网格和过多箭头，改成手绘场景。
- 太像旧案例：保留核心意思，换掉主物件和当前 IP 角色的动作。
- 文字错：优先局部编辑；错得多就重生成并减少标注数量。

## 整篇文章（Set-level）

- 图片共享选定的**视觉母题**（一个世界），因此整套图片读起来像一个速写本——同时每张图片仍然只表达一个思想。
- 反复出现的角色在图片中看起来**一致**（在支持的后端上使用相同的 seed；否则使用稳定的文本描述）。
- 除非用户为每张图片设置了不同的宽高比和标注语言，否则在整个集合中它们是**统一的**（按文章的选择在集合内是统一的）。
- 如果在弱渲染器上标注持续失败，将**整篇**文章切换到无文字+说明模式——一个一致的选择，而不是混合模式。
- 如果一张图片的世界偏离了母题，在其提示中添加一个短语的母题锚点（例如，“在一个杂乱的车间里，”）并重新生成——不要让集合分裂。

## 交付判断

高质量图应该让读者先觉得“有点怪”，然后 1 秒内看懂结构。

如果第一眼像教程页，而不是白纸上的怪诞产品草图，就不合格。
